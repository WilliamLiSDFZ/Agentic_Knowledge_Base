# Mobile-Bench: An Evaluation Benchmark for LLM-based Mobile Agents

**Source**: https://aclanthology.org/2024.acl-long.478/

## [POSITIVE] API + UI Hybrid Action Space
Combining API calls (via ADB commands) with traditional UI operations, allowing agents to choose between the two for each action step

**Delta**: +6.57% PassRate on SAST, >20% CheckPointl2 improvement on SAMT
**Condition**: GPT-4 agent on SAST and SAMT tasks; ablation study removing API calls

**Evidence**: "even in SAST, the PassRate has decreased by 6.57% (from 80.96 to 74.39). Furthermore, the values for CheckPointsl2 exhibit a more pronounced decrease after API removal, with a drop exceeding 20% in SAMT."

## [POSITIVE] Observation-Thought-Action (Chain-of-Thought Planning)
Generating an explicit thought step between observation and action, allowing the agent to reason about current task status and next steps before acting

**Delta**: PassRate: 76->24 on SAST, 77->20 on SAMT when removed
**Condition**: GPT-4 agent on SAST (subset 50) and SAMT (subset 200)

**Evidence**: "without the observation-thought step, the agent is almost unable to complete the task(77->20, 76->24), which is because it cannot determine the next action category and the current task status."

## [POSITIVE] Overall Task Planning
Generating a comprehensive task plan at the start outlining necessary applications and sub-tasks before iterative execution begins

**Delta**: PassRate: 77->62 on SAMT, 76->72 on SAST when removed
**Condition**: GPT-4 agent on SAST (subset 50) and SAMT (subset 200); more impactful on complex multi-task scenarios

**Evidence**: "In more complex tasks SAMT, losing the plan has more negative consequences(77->62)."

## [POSITIVE] XML-to-HTML UI Representation Conversion
Converting Android XML UI tree structure into HTML format for LLM consumption, based on the assumption that LLMs are better trained on HTML than XML

**Delta**: outperforms baseline
**Condition**: Applied universally in the baseline model for all agents and tasks

**Evidence**: "we convert XML to HTML, as the training data for LLMs is predominantly sourced from the Internet, which includes numerous HTML files. Therefore, we believe that LLM has a better understanding of HTML than XML."

## [POSITIVE] 3-Shot In-Context Learning
Providing 3 demonstration examples in the prompt during inference for all evaluated LLMs

**Delta**: not quantified separately
**Condition**: Applied to all LLMs (GPT-3.5-turbo, GPT-4, LLaMA-13B, LLaMA-70B) across all task categories

**Evidence**: "The experiments are conducted with a 3-shot in-context learning under sampling temperature of 0.1."

## [POSITIVE] CheckPoint Evaluation Metric
A process-based evaluation metric with three checkpoint types (Package, Key phrase, API) and three logical relationships (sequential, conjunctive, disjunctive) to assess intermediate steps rather than only final outcomes

**Delta**: reveals discrepancy: LLaMA shows high PassRate (44.58%) but low CheckPoint coverage (34.85%)
**Condition**: Used as a more accurate diagnostic metric compared to PassRate alone; exposes premature task termination behavior

**Evidence**: "LLaMA, which exhibits a high PassRate (44.58%) but low CheckPoint coverage (34.85%)"

## [NEUTRAL] GPT-4 Data Augmentation for SAMT and MAMT
Using GPT-4 to generate complex single-app multi-task and multi-app multi-task queries, since real data for these categories is scarce or low quality

**Delta**: Overlap score: SAST=0.94, SAMT=0.85, MAMT=0.80
**Condition**: Applied to SAMT and MAMT data generation; quality verified via human evaluation with 0.80 overlap for MAMT vs 0.94 for SAST

**Evidence**: "all MAMT data is generated by instructions, its quality does not exhibit an unacceptable gap compared to SAST."

## [NEGATIVE] Actions History Compression (Truncation to Last 20 Entries)
On MAMT tasks, compressing the actions history by retaining only the most recent 20 entries due to context length limitations

**Delta**: MAMT PassRate as low as 15.5% (GPT-3.5) and 26.5% (GPT-4)
**Condition**: Applied to GPT-4 on MAMT tasks due to standard context length limit; GPT-3.5 uses 16K context interface instead

**Evidence**: "On MAMT data, due to context length limitations, a compression is applied to the actions history by retaining only the most recent 20 entries. as the actions history increases, its ability to accurately judge task progress becomes increasingly challenging."

## [NEGATIVE] Premature Task Termination (PassRate Misjudgment)
Models with poorer performance prematurely terminate tasks even when not completed, inflating PassRate scores

**Delta**: LLaMA PassRate 44.58% vs CheckPointl2 34.85% on SAST
**Condition**: Observed in LLaMA-13B and LLaMA-70B; also present to some degree in GPT-3.5 on SAMT

**Evidence**: "models with poorer performance exhibit PassRate misjudgments: they prematurely terminate even when the task is not completed. This phenomenon is also present in LLaMA, which exhibits a high PassRate (44.58%) but low CheckPoint coverage (34.85%)."

## [NEGATIVE] Greedy Exploration Behavior in Multi-App Tasks
LLMs tend to stay within the current application and struggle to determine when to exit and transition to the next application in multi-app tasks

**Delta**: MAMT PassRate: 15.5% (GPT-3.5), 26.5% (GPT-4)
**Condition**: Observed specifically on MAMT (Multi-App-Multi-Task) scenarios for all evaluated LLMs

**Evidence**: "LLMs often exhibit greedy exploration behavior when completing tasks, meaning they struggle to determine when to exit the current application and transition to the next one. This tendency is particularly prevalent in certain generation tasks."

## [NEUTRAL] Task Difficulty-Based Step Limit
Setting different maximum step limits per task category: 10 for SAST, 20 for SAMT, and 50 for MAMT

**Delta**: not quantified separately
**Condition**: Applied to all agents and all task categories to control evaluation cost and reflect task complexity

**Evidence**: "we preset different maximum step limits for tasks based on their difficulty levels. For the three categories of SAST, SAMT, and MAMT, we set the max step to 10, 20, and 50 respectively."

## [NEGATIVE] UI-Only Operations (without API)
Relying solely on UI interactions (click, scroll, input) without API calls for task completion

**Delta**: -6.57% PassRate on SAST, >20% CheckPointl2 drop on SAMT, increased average steps across all categories
**Condition**: Ablation condition (w/o API) evaluated on GPT-4 across SAST, SAMT, and MAMT

**Evidence**: "the inability to accurately scroll pages, inefficient exploration of page functionality, and failure to click graphical buttons are the primary reasons for the low efficiency of UI operations."

## [NEUTRAL] Low Sampling Temperature (0.1)
Using a low temperature of 0.1 during LLM inference to reduce output randomness

**Delta**: not quantified separately
**Condition**: Applied uniformly to all LLMs evaluated on Mobile-Bench

**Evidence**: "The experiments are conducted with a 3-shot in-context learning under sampling temperature of 0.1."

## [NEUTRAL] Plan's Effect on Application Selection (CheckPointl1)
Removing the overall plan has negligible effect on whether the correct application is selected, since application selection is primarily driven by API calls

**Delta**: CheckPointl1: 82->82 on SAST, 63->63 on SAMT when plan removed
**Condition**: GPT-4 ablation study (w/o plan) on SAST and SAMT

**Evidence**: "they will have almost no impact on CheckPointl1 (82->82 63->63), because the application selection is almost done by the API Call."
